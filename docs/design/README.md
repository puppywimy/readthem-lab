# 디자인 가이드라인

`index.html`은 Readthem Lab의 새 디자인 기준을 보여 주는 정적 프로토타입입니다. 홈, 도서 검색, 도서 상세, 마이페이지, 관리자, 회원가입(약관) 화면이 있고, `front/`에 반영되어 있습니다. API가 지원하지 않는 항목(저자·리뷰 수·조회수 표시, 전체 도서 목록, 상세 필터, 약관 동의 가입)은 `front/`에서 뺐습니다. 디자인과 UI/UX를 보여주기 위한 용도이므로, API 연동이나 복잡한 기능은 여기서 구현하지 않습니다.

브라우저로 `index.html`을 바로 열면 됩니다. 글꼴과 표지를 불러오려면 인터넷 연결이 필요합니다.

- 맨 위 검은 막대는 화면 이동용 패널입니다. 화면 이동, 로그인 상태(비로그인, 회원, 관리자), 화면 상태(기본, 비어 있음, 로딩)를 바꿀 수 있고, 실제 서비스에는 넣지 않습니다.
- 회원 서재와 오류 화면은 전용 시안이 없어, `front/`에서는 내 서재와 상태 메시지 스타일을 재사용합니다. 이전 디자인은 git 기록에서 볼 수 있습니다.
- 도서, 리뷰, 회원은 샘플 데이터입니다. 표지는 Open Library의 원서 표지입니다.
- 표지는 불러오는 동안 스켈레톤으로 보이고, 다 불러오면 서서히(0.4초 페이드) 나타납니다. 썸네일이 없거나 불러오지 못하면 패널과 같은 바탕(`--surface`)에 책등 띠와 얇은 테두리(`--line`)를 두른 빈 책 모양에 "썸네일이 없습니다" 문구를 보여 줍니다. 도서마다 색이 다른 글자 표지는 쓰지 않습니다. 글자를 넣기 어려운 작은 표지(홈 순위 목록 2위 이하, 홈 인기 리뷰 카드 하단, 관리자 도서 표)는 문구가 든 큰 표지를 캡처한 이미지(`front/public/covers/empty-light.png`, `empty-dark.png`)를 테마에 맞춰 깝니다. 표지 배경색이나 문구를 바꾸면 이 두 이미지도 다시 캡처해야 합니다. 홈 표지 벽은 정적 표지를 먼저 보여 주므로 스켈레톤·안내 문구를 쓰지 않습니다.
- `dev` 프로필의 초기 데이터(`BaseInitData.work2`)는 이 샘플 도서, 회원, 리뷰, 찜, 집계 값을 그대로 넣습니다. 여기에 썸네일 없음 안내를 확인하기 위한 표지 없는 도서 4권(시안에는 없음)을 더합니다. `test` 프로필은 테스트가 의존하는 기존 데이터(`work1`)를 씁니다. 회원이 한 명이라도 있는 DB에는 적용되지 않으므로, 기존 로컬 DB는 지워야 반영됩니다.
- 색상 토큰과 레이아웃은 `.home-a` 안에 있습니다. 모서리는 표지 4px, 패널 16px, 상호작용 요소 pill입니다.
- 홈 헤더의 `도서 검색`은 페이지 최상단으로, `독서 트렌드`와 `리뷰`는 각 섹션으로 이동합니다. `내 서재`는 로그인해야 보이고, `관리자`는 관리자 계정에만 강조 표시로 보입니다.
- `front/` 홈은 로딩 중에도 레이아웃이 밀리지 않게 자리를 잡아 둡니다. 순위·리뷰·최근 도서는 실제 콘텐츠와 같은 크기의 스켈레톤을 쓰고, 히어로 표지 벽은 `front/public/covers/`의 정적 표지 15장(Open Library의 큰 크기 원서 표지, 세로 500px)을 먼저 보여 준 뒤 실제 표지가 다 불러와지면 한 장씩 서서히(0.8초 페이드) 덮습니다. 표지 벽(`.wall`)은 계속 움직이므로 `overflow-anchor: none`으로 스크롤 앵커 후보에서 뺍니다. 빼지 않으면 `/#home-rank`에서 새로고침할 때 Chrome이 움직이는 표지를 기준으로 스크롤을 복원해 위치가 어긋납니다.
- 내 서재의 로딩 화면(`MyPageSkeleton`)은 실제 화면과 같은 클래스로 프로필·통계·탭·목록 행 자리를 잡아, 로딩 전후로 상단 띠 높이와 탭 위치가 바뀌지 않게 합니다. 탭 이름은 정해져 있으므로 스켈레톤 대신 글자를 그대로 보여 줍니다. 강조색 띠(`.band`) 위의 스켈레톤은 회색(`--surface`) 대신 띠와 같은 색조의 짙은 색을 씁니다.
- 860px 이하에서는 헤더 메뉴가 로고 아래 줄로 내려오고, 탭은 한 줄 가로 스크롤이 됩니다.
- `widget-sample.svg`는 위젯의 새 디자인 샘플입니다. 작성한 리뷰와 보고 싶어요한 책의 표지를 섞어 홈 표지 벽처럼 위아래로 흐르게 하고, 다른 정보는 넣지 않습니다. README의 `<img>`에서도 보이도록 표지를 파일 안에 내장했고, `widget/` 렌더러에는 아직 반영하지 않았습니다.
- 도서 검색의 상세 필터(태그, 최소 별점, 출간 연도)는 UI만 있고 결과에는 적용되지 않습니다. 860px 이하에서는 `상세 검색` 버튼으로 접힙니다.
- 도서 상세에서 좋아요가 가장 많은 리뷰에는 `베스트 리뷰` 배지를 붙입니다. 좋아요가 0개면 붙이지 않습니다. 베스트 리뷰는 고정이고, 정렬(최신순 기본, 인기순)은 그 아래 목록에만 적용됩니다. 로그인한 회원이 이 책에 쓴 리뷰는 `내 리뷰` 배지를 붙여 베스트 리뷰 위에 고정합니다. 내 리뷰가 좋아요도 가장 많으면 베스트 리뷰를 따로 두지 않고 내 리뷰에 두 배지를 함께 붙입니다. 각 리뷰는 작성자 줄 아래에 별 5개와 점수를 강조색으로 보여 주고, 내 리뷰의 `수정`·`삭제`는 그 줄 오른쪽 끝에 둡니다. 이미 리뷰를 쓴 책에서 `리뷰 쓰기`를 누르면 모달을 열지 않고 "이미 이 책에 리뷰를 작성했습니다."라고 알립니다.
- 회원가입은 GitHub 인증 뒤 신규 회원에게만 약관 동의를 받는 흐름을 가정했습니다. 약관 문구는 샘플이며 법률 검토가 필요합니다.
- 리뷰 쓰기·수정 모달에서 별점은 필수, 리뷰와 태그는 선택입니다. 별점은 별 5개를 눌러(누른 채 끌어도 됨) 0.5 단위로 고르고, 포커스가 있으면 방향키로도 바꿉니다. 고르지 않으면(0.0) 등록되지 않습니다. 태그는 Enter로 칩이 되고, 칩의 x 버튼이나 빈 입력창의 백스페이스로 지웁니다. 이미 넣은 태그를 다시 넣으면 입력창이 흔들리며 안내 문구가 바뀝니다. `front/`에서는 백엔드 검증에 맞춰 태그를 5개, 태그당 30자로 제한하고(6번째도 같은 방식으로 안내), Enter를 누르지 않고 남겨 둔 글자도 등록할 때 태그로 넣습니다. 내용이 없는 리뷰는 목록에서 본문 줄 없이 보여 줍니다.
